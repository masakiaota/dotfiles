# ワークツリーの整理

## 承認の境界

- 調査と対象一覧の作成までを先に行う。残すディレクトリとゴミ箱へ移すディレクトリを絶対パスで提示し、その具体的な一覧に対するユーザーの明示的な承認を待つ。
- 「不要なものは消して」「接続解除してよい」という最初の依頼だけで、調査後の対象一覧が承認されたと扱わない。「作業前に教えて」は、一覧の通知直後に実行してよいという意味に解釈しない。
- 一覧を提示したターンでは変更せず、承認を求めて応答を終える。このスキルの上記規定により承認が必要であることを短く説明し、使用中のSKILL.mdへのリンクを示す。
- すでに具体的な一覧への承認を受けている場合は重ねて求めない。対象追加や重要な状態変化があれば、変更部分について改めて承認を得る。

## 調査と提示

1. 対象リポジトリで `git worktree list --porcelain` を読み、登録済みの絶対パス、ブランチまたはdetached HEAD、ロック、存在しない場所を確認する。名前が似ているだけの別クローンを対象に含めない。
2. ユーザーが指定したメインのディレクトリを保持する。指定がなければ現在の作業場所を候補として示すが、Gitの主ワークツリーと同一だと決めつけない。共通Git管理ディレクトリを含む場所は移動対象から保護する。保持対象が曖昧なら確定するまで実行しない。
3. 移動候補ごとに `git -C <path> status --short` で未コミット変更と未追跡ファイルを調べる。ロックされた場所や使用中と判明した場所は、その事情を示して保持候補にする。変更があるだけで勝手に破棄しない。
4. 残す場所と移動する場所を分け、各絶対パス、ブランチ、未コミット変更の有無、確認できなかった点を簡潔に示す。ブランチは保持し、ディレクトリはゴミ箱へ移す方針を明示して承認を求める。存在しない場所は登録解除のみの対象として区別する。

## 承認後の実行

1. 登録一覧と対象の状態を再確認する。承認された正確なパスだけを操作し、ワイルドカードやディレクトリ名の部分一致で対象を広げない。
2. macOSではFinderのゴミ箱移動など、OSのゴミ箱機能を使う。他の環境でも利用可能なゴミ箱機能を使う。ゴミ箱への移動が失敗した場合は停止し、`rm -rf` や `git worktree remove --force` に切り替えない。同名のゴミ箱項目を上書きしない。
3. ファイルの移動成功を確認してからGitの登録を解除する。`git worktree prune --dry-run --verbose --expire now` で解除予定を確認し、承認外の登録まで消えない場合に限り `git worktree prune --expire now` を実行する。承認外の対象が含まれる場合は停止して報告する。
4. 登録解除はワークツリー固有のGit管理情報も失わせる。ステージ状態などの保持が必要な場合は、解除前に対象の管理情報を退避する。ゴミ箱からフォルダを戻すだけでGitの接続まで復元できるとは説明しない。
5. `git worktree list --porcelain` と移動結果を確認し、残った場所、移動できた件数、登録解除の成否を報告する。途中失敗があれば完了部分と未完了部分を区別する。

ブランチ削除、コミット、stash、作業中のプロセス停止は、この整理依頼に含めない。
